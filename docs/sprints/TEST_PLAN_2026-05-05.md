# Test Plan — Audit Pasca Pembersihan Data Fake

**Tanggal:** 5 Mei 2026
**Konteks:** Setelah penghapusan klaim ISO 9001, angka 500+/1000+/98%/96%/138+/1.500, ticker palsu, aggregateRating, dan penyederhanaan visual ke arah minimalist.
**Tujuan:** Memastikan tidak ada regresi (broken page, broken link, broken assertion, broken layout) setelah perubahan menyentuh 12+ file.

---

## 1. Ruang Lingkup

### Yang Berubah (impact area)
- `config/landing_metrics.php` — semua stats angka di-null-kan
- 8 view sections v2 (hero, trust-strip, live-progress, newsletter, ecosystem-hub, final-cta, faq, others)
- 2 halaman pages (process, about)
- 2 partials (footer, head)
- 1 service-inquiry create page

### Risiko Regresi
| # | Risiko | Indikator |
|---|--------|-----------|
| R1 | Null pointer pada Blade saat render stats yang sekarang null | 500 ISE pada route landing |

| R3 | Schema.org JSON-LD malformed setelah hasCredential dihapus | Invalid structured-data |

## 2. Strategi Tiga Lapis

### Lapis A — Sanity Testing (cepat, surface-level)
**Goal:** Memastikan build kompilasi & route smoke pass dalam <60 detik.
**Aktivitas:**
- A1. `php -l` syntax check pada file yang diedit (12 file)
- A2. `php artisan route:list` tidak error
- A3. `php artisan view:clear && cache:clear && config:clear` bersih tanpa error
- A4. `npm run build` exit 0 dengan size CSS landing dalam range normal (±10%)

### Lapis B — Smoke Testing (route render, response 200)
**Goal:** Setiap halaman publik me-render 200 OK + payload non-zero + tanpa exception.
**Aktivitas:**
- B1. ID locale: `/`, `/tentang`, `/proses`, `/harga`, `/layanan`, `/faq`, `/blog`, `/login`, `/cek-perizinan-gratis`
- B2. EN locale: `/en`, `/en/about`, `/en/process`, `/en/pricing`, `/en/services`, `/en/blog`
- B3. Static: `/sitemap.xml`, `/robots.txt`, `/feed.rss`, `/feed.atom`, `/health`
- B4. Cek HTML render: tidak ada string `Undefined`, `ErrorException`, `htmlspecialchars()` warning, `Trying to access`
- B5. Cek HTML render: zero occurrence pada 8 string fake yang sudah dihapus (ISO 9001, 500+, 138+, 98%, 96%, 1.500 subscribers, aggregateRating, hasCredential)
- B6. Cek HTML render: positive occurrence pada string capability yang sekarang dipakai (12+ Tahun, Sejak 2014, Bilingual)

### Lapis C — Regression Testing (PHPUnit feature suite)
**Goal:** Memastikan asersi otomatis yang sudah ada tetap pass; perbaiki yang gagal akibat perubahan copy.
**Aktivitas:**
- C1. Jalankan `php artisan test --testsuite=Feature --filter=LandingPageTest`
- C2. Jalankan `php artisan test --testsuite=Feature --filter=ServiceInquiryControllerTest`
- C3. Jalankan `php artisan test --testsuite=Feature --filter=DesignSystemTest`
- C4. Jalankan `php artisan test --testsuite=Feature --filter=BladeComponentTest`
- C5. Jalankan `php artisan test --testsuite=Feature --filter=SeoIntegrationTest`
- C6. Jika 1–5 hijau, jalankan **full Feature suite** untuk verifikasi cross-domain (Auth, Admin, Client, Hrm, Email, etc.)
- C7. Unit tests: `php artisan test --testsuite=Unit`

---

## 3. Kriteria Kelulusan

| Lapis | Wajib | Toleransi |
|-------|-------|-----------|
| Sanity (A) | Semua exit 0 | — |
| Smoke (B) | 100% route 200, zero string fake terdeteksi | — |
| Regression (C) | Landing/SEO/Inquiry tests 100% pass; full suite ≥95% pass | Tes yang gagal harus ROOT CAUSE pada perubahan; bila pre-existing failure (tidak terkait), didokumentasikan |

---

## 4. Eksekusi & Pelaporan
1. Jalankan A → B → C berurutan
2. Setiap kegagalan didiagnosa: regresi vs pre-existing
3. Regresi dari sesi ini → diperbaiki saat itu juga
4. Pre-existing → dicatat ke memori repo, tidak diperbaiki tanpa permintaan
5. Ringkasan akhir: tabel hasil per lapis + daftar fix yang diterapkan
